# v0.2.2

## Hugo floor 0.169.0

The Hugo export now needs Hugo 0.169.0 or newer.

- `hugo.toml` sets 0.169.0 as the minimum Hugo version.
- The base layout stops an older Hugo build with this error: `this site needs Hugo 0.169.0 or newer, found <version>`.
- `export -g hugo` prints a warning on stderr when the `hugo` on PATH is older. The exit code does not change.
- `doctor` has a new `hugo` line. Below the floor it shows a WARNING and the exit code stays 0. When Hugo is missing it shows `not installed (only needed for export -g hugo)`.
- CI pins Hugo 0.169.0.

## Tufte style

The Hugo layouts now use the Tufte style. The export vendors Tufte CSS and the ET Book fonts in `static/vendored/tufte/`, so the site needs no network and no CDN. Source pages show badges for the review state, citation, authors and published date. A superseded page shows a banner.

## Scaffold update rule

The export now updates the scaffold. It looks at each scaffold file:

- A missing file is created. It prints `created <path>`.
- A file that is byte for byte a version that zk-chef shipped is replaced. It prints `updated <path>`.
- Any other file counts as your edit and is kept. In text mode it prints `kept your <path>` and a diff of your file against the current version.
- `hugo.toml` is replaced only when it equals a shipped template rendered with the title of the root page. Another Hugo config in `DIR` stops the export from creating `hugo.toml`.
- `static/vendored/` belongs to zk-chef. The export overwrites its files when they differ, so your edits there are lost. Use your own stylesheet. A v0.2.0 or v0.2.1 export has no `static/vendored/` directory, so the export creates it.

To restore a file to the current version, delete it and export again.

## `export --json`

`export --json` has two new arrays, `updated` and `kept`, beside `scaffolded`.
