# v0.3.0 (Draft)

v0.3.0 changes the vault format. A v0.3.0 binary does not work on a v0.2 vault: every verb that reads a vault exits with code 2 when the vault's `min_version` is older than 0.3.0. Keep zk-chef v0.2.x for an old vault, or run `zk-chef init` for a new one. There is no migration command.

## Vault layout

- All notes, hubs, sources and logs are in one flat folder, `notes/`. The root page stays `index.md`. `raw/` and `keys/` stay. Subfolders in `notes/` are an error.
- A note's ID is its file name stem: 6 lowercase letters and digits, for example `k3x9qa`. There is no `id:` field. The only fixed stem is `index`.
- Links are `[[stem|Title]]`.
- `init` seeds only `index.md`. Make a Sources hub or a Projects hub when you need one.
- `.zk-chef/config.toml` has no `index_id`, `projects_id` or `sources_id`. `word_count_warn` stays.

## Frontmatter and tags

- Every note has `title`, `date` (UTC, ISO 8601 with `Z`, written once by the template) and `tags`. `aliases` is optional.
- Kind and state are tags, not fields:
  - exactly one `kind:note`, `kind:source`, `kind:hub` or `kind:log`;
  - `review:unreviewed`, `review:reviewed` or `review:disputed` on a source;
  - `status:superseded` on a superseded note or source;
  - `topic:<value>`, lowercase kebab case, `/` for nesting;
  - `type:<value>`, lowercase kebab case, on logs only.
- A key or a tag that the note's kind does not list gives `W_UNKNOWN_KEY` or `W_UNKNOWN_TAG`.
- A superseded note has the `status:superseded` tag, `superseded_by: <stem>`, and the body line `Superseded by [[stem|Title]]` after the Hubs line. Lint requires all three. Hubs and logs cannot be superseded.

## Sources

- A source has `url` and `accessed` (`YYYY-MM-DD`), or `raw` and `sha256`, or both. `authors` and `published` are optional.
- `citation:` is removed. Inline `[n]` citations and the numbered `## References` list stay.
- `## Extract` is optional.
- A raw copy is `raw/<stem>` plus the extension of the original name, or of the download's Content-Type, or no extension.

## Review

`zk-chef review` still signs the verdict with GPG. The signed message is now `vault-review v2`. It covers the raw path and sha256 when the source has a raw file, else the `url` and `accessed`. Lint compares the latest block's verdict with the `review:` tag.

## Kinds and templates

- One template per kind. `zk new` groups are removed. Create notes with the zk aliases `zk note`, `zk source`, `zk hub` and `zk log`, each with `--title "<title>"`.
- A log has a `## Updates` section. Each entry is a `### YYYY-MM-DD` heading, newest first. Other H2 sections may come before `## Updates`.

## Hubs and links

- The Hubs line separator is `, `: `Hubs: [[a1b2c3|Topic]], [[d4e5f6|Other]]`.
- A hub that names a parent hub must be linked in the parent's body (`W_HUB_UNLISTED`).
- `GAP:` lines are no longer used.

## Lint codes

- New: `W_UNKNOWN_KEY`, `W_UNKNOWN_TAG`, `W_HUB_UNLISTED`, `W_LOG_HEADING`.
- Removed: `E_WRONG_FOLDER`, `W_HUB_MAP`, `W_DEAD_END`. `W_MARKER` no longer matches `GAP:`.

## Commands

- `-r` is a short form of `--root` on every verb that has `--root`.
- The `fix` verb is removed. Use `zk-chef lint --fix`.
- `zk-chef lint --children HUB` lists the notes whose Hubs line names `HUB`.
- `ingest` needs at least one `--hub`. `ingest URL --no-raw` makes a source note with `url` and `accessed` and downloads nothing. `ingest` makes a new note again when `zk new` returns an existing file.

## Export

- `export -g hugo` has a new flag, `-s/--style plain|tufte`. `plain` is the pre-Tufte layout with the Hugo floor check and a review line on source pages. `tufte` is the v0.2.2 layout.
- The site keeps its Style in `.zk-chef-site.json`. Without `--style`, the export uses that Style. When the file is missing, the export uses `tufte` if `static/vendored/tufte/` exists, else `plain`.
- `plain` removes `static/vendored/tufte/`.
- Exported frontmatter: `kind`, `review` and `status` come from the tags. `date` and `accessed` are new. `topic:` and `type:` tags stay in `tags`. `aliases` is not exported.
- The export no longer adds a `Superseded by` line. The vault note has one.

## Decisions

Made on 2026-11-14 from Notion "Agent Zettelkasten skill design", subpages 2 to 5, and the source fields of subpage 6.

1. Subpage 6: take the source fields and raw naming only. Keep numbered `[n]` IEEE citations and `E_CITATION`. Leave out `References: none`, URL list-item references and `W_UNREVIEWED_SOURCE`.
2. No migration verb. v0.3.0 needs a fresh `init`. The gate refuses a vault with `min_version` older than 0.3.0.
3. The Hubs line and reachability check runs on the full staged tree on every commit (subpage 4's incremental check is rejected; lint takes about 0.05 s). No `lint --all`.
4. Keep the Prose exemption from `W_STALE_ALIAS` and from the alias fix (v0.2.1, #27).
5. Keep GPG review (ADR 0003). A source with no raw file signs `url` and `accessed`.
6. Remove `citation:`. Keep `## Extract` as optional, because `raw/` is not indexed by zk.
7. `ingest` needs `--hub`. Sources and Projects hubs are made on demand.
8. `fix` becomes `lint --fix`. Add `lint --children HUB`.
9. `ingest --no-raw` makes a source with only a URL.
10. The site's Style is kept in `.zk-chef-site.json`, not in the manifest (ADR 0004). A missing file falls back to the `static/vendored/tufte/` check.
11. Log types are `type:<kebab>` tags on logs only. `topic:` is a free tag namespace.
12. Logs need `## Updates` with `### YYYY-MM-DD` entries, newest first (`W_LOG_HEADING`).
13. `init` writes the current UTC time to `date` in `index.md`.
14. `plain` is the #32 layouts plus an unstyled review line, with new hashes in `scaffoldHashes`.
15. A link with the wrong case needs no new check: stems are generated in lower case, and lint resolves links exactly, so a wrong case is already `E_BROKEN_LINK`.
16. The superseded body line is required by lint. Export does not add it.
17. Drop `W_DEAD_END`. Keep `W_WORD_COUNT`.
18. Export unpacks kind, review and status from the tags, keeps `topic:` and `type:` as `tags`, and adds `date` and `accessed`.
19. The term is **Style** (`-s/--style`), not theme, because a Hugo theme is a different thing.
20. A source needs `url` (with `accessed`), or `raw` with `sha256`, or both. A local file has no URL.
21. A raw extension comes from the original name, then the Content-Type, then none.
22. `ingest` tries `zk new` up to 3 times when it returns an existing file, then exits with code 1.
